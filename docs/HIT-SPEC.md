# 때리기(⚾) 기능 명세 — 구현 기준 문서

프로젝트: `~/ah-hit-dev` (홀덤 게임 v2 "AFTER HOURS" 개발 사본. Node + ws, 클라이언트는 `public/` 의 ES 모듈 + three.js).
**라이브 폴더 `~/Desktop/after-hours-holdem` 과 3200 포트 서버는 절대 건드리지 말 것** (친구들이 접속 중일 수 있음). 모든 작업·시험은 이 사본에서, 포트는 각자 배정된 것만.

## 1. 사용자가 확정한 규칙 (바꾸지 말 것)
1. 판 도중에도 때릴 수 있다.
2. 쿨다운은 **테이블 전체**: 때린 핸드 H, H+1, H+2 는 아무도 못 때리고, **H+3 부터 가능**. (같은 핸드에서 이미 누가 때렸으면 다른 사람은 못 때린다.)
3. 맞은 사람은 **맞은 뒤 처음 시작하는 핸드를 기절해서 쉰다**: 그 핸드에서 **패를 아예 받지 않고**(자동 폴드가 아님) 블라인드도 안 낸다. 핸드가 시작될 때 쓰러지는 모션, 그 핸드가 끝나면 깨어나는 모션.
4. 맞은 사람에게 문구 **"기절로 인한 다음 핸드는 플레이가 불가합니다"**. 다음 핸드를 뛰고 싶으면 맞은 사람이 때린 사람에게 **1,500원**을 보내면 된다(때린 값은 1,000이라 때린 사람은 +500).
5. **방 설정이 아니라 인게임에서 방장이 켜고 끄는 스위치**, 기본값 **켜짐**. 꺼져도 버튼은 사라지지 않고, 누르면 **"방장 권한으로 폭력은 안됩니다."** 문구.
6. **연습 테이블도 동일한 규칙. 봇도 합의금을 내고 봇도 때린다.**
7. **때리기·합의금으로 인한 금액 변동은 실시간으로 반영** (누르는 즉시 서버가 칩을 옮기고 모두의 화면 숫자가 바로 바뀐다).
8. 모션은 시안 B(만화 폭주): `public/punch.js` 의 `styleB`. 렉 금지(60fps 유지, 새 조명·그림자·타이머 만들지 말 것).

## 2. 서버 규칙 (이미 `engine.js` / `server.js` 에 구현됨 — 읽고 맞춰 쓸 것)
상수: `HIT_COST=1000, STUN_PAY=1500, HIT_COOLDOWN=3, HIT_ANIM_MS=11000` (engine.js 에서 export).

Table 필드: `hitOn`(기본 true), `hitSeq`(때린 횟수), `lastHitHand`(-99=없음), `lastHitBy`(이름), `hitUntil`(연출 끝 시각 ms). Player 필드: `stun`(`''|'pending'|'out'`), `stunBy`(때린 사람 token).

메서드:
- `hitCheck(hi, vi)` → 부작용 없이 가능 여부. 안 되면 **이유 문장**, 되면 `null`. (봇·시험이 사용)
- `hit(token, idx)` → 검증 후 때리는 사람 `chips -= 1000`, 맞는 사람 `chips += 1000` (앞 스택만; 팟·베팅·올인 표시는 안 건드림), 맞는 사람 `stun='pending'`, `emit({k:'hit', i:때린사람, to:맞은사람, amt:1000})`, 판 진행 시간은 늘리지 않음.
- `payStun(token)` → 맞은 사람이(`stun==='pending'`일 때만) `chips -= 1500`, 때린 사람 `chips += 1500`, `stun=''`, `emit({k:'pay', i:낸사람, to:받은사람, amt:1500})`. 때린 사람이 이미 없으면 그냥 풀림. 기절 핸드가 이미 시작됐으면 `'이미 이번 핸드를 쉬는 중이에요'`.
- `hitSwitch(token, on)` → 방장만.
- `startHand()` 에서 `promoteStuns()`: `pending → out`(때린 사람이 있을 때), `out` 인 사람은 `elig` 에서 빠짐(패 안 받음, 블라인드 안 냄, `inHand=false`, `lastAction='기절'`). 기절 때문에 `elig<2` 면 기절을 풀어 준다. 연습 테이블에서 사람이 기절해도 봇끼리 그 핸드는 진행.
- `endHand()` 에서 `out → ''` (깨어남).
- 메시지(server.js): `{t:'hit', i}`, `{t:'payStun'}`, `{t:'hitSwitch', on}`. 실패는 `{t:'error', msg}` 가 보낸 사람에게만 가고 상태는 안 바뀐다.
- `view(token)` 추가 필드: `hit: {on, cost, pay, cooldown, lastHitHand, lastHitBy, busyUntil, seq}`, `players[i].stun`, `players[i].stunBy`(때린 사람 index, 없으면 -1).
- 이벤트(`events` 배열, id 순서): `{k:'hit', i, to, amt}`, `{k:'pay', i, to, amt}` — 연출 시간(`emit` 의 dur 표)에 없으니 판 진행 타이머를 늘리지 않는다.
- 거절 문구(서버 기준, 클라이언트도 같은 문구를 쓴다): `'방장 권한으로 폭력은 안됩니다.'`, `'이번 핸드에는 이미 ○○님이 때렸어요'`, `'때리기는 연달아 쓸 수 없어요 · N핸드 뒤부터 가능해요'`, `'지금 ○○님이 때리는 중이에요'`, `'칩이 부족해서 때릴 수 없어요 (때린 뒤에도 빅블라인드 이상 남아야 해요)'`, `'칩이 없거나 나간 사람은 때릴 수 없어요'`, `'남는 사람이 적어서 때릴 수 없어요 (기절하면 판이 안 돌아가요)'`, `'기절한 사람은 때릴 수 없어요'`, `'마지막 핸드에는 때릴 수 없어요'`, `'휴식 중에는 때릴 수 없어요'`, `'칩이 부족해서 합의금을 낼 수 없어요'`.
- 서버가 반드시 지키는 안전 규칙(바꾸지 말 것): 때리는 사람은 낸 뒤에도 칩이 남아야 한다 → '칩 0인데 올인 표시 없음' 상태가 생기지 않는다. 합의금도 `chips > 1500` 일 때만. (`docs/hit-fuzz-prototype.js` 가 가드 없이 옮기면 칩이 음수가 되고 올인 표시가 어긋남을 보였다.)

## 4. 봇 명세 (`bot.js`)
- 연습 테이블에서만 동작(`t.practice`). 기존 `tick(t)` 에 이어 붙인다(상태가 바뀔 때마다 호출됨). `HOLDEM_FAST`(`t.opts.pace===false`) 면 대기 없이 5ms.
- **합의금**: 봇이 `stun==='pending'` 이 되면(`t.hitSeq` 변화로 감지) 사람처럼 1.5~4.5초 뒤(타이머 `p._payT`)에 지불 여부를 정한다. 성향별 확률 tight 0.6 / balanced 0.75 / loose 0.9, 그리고 `chips > STUN_PAY + 2*bb` 일 때만. 지불은 `t.payStun(p.token)`. 안 내면 그냥 기절.
- **때리기**: 각 핸드가 끝나 `phase==='showdown'` 이 된 순간(핸드당 한 번) 봇들이 굴린다. 기본 확률 tight 0.02 / balanced 0.05 / loose 0.09 + 쇼다운에서 크게 진 봇(`total ≥ 4*bb` 인데 `won===0`) +0.20 + 방금 자기를 때린 사람이 있으면(복수) +0.15. **핸드당 많아야 한 번**만 예약(`t._botHitT`, 1.2~4초 뒤, 빠른 모드 5ms). 대상: 크게 진 경우엔 그 핸드 최대 승자, 복수면 때린 사람, 아니면 `hitCheck` 를 통과하는 사람 중 무작위. **실행 직전에 `t.hitCheck(botIdx, target)===null` 인지 다시 확인**하고 `t.hit(bot.token, target)`.
- 봇은 사람과 똑같은 규칙을 지킨다(쿨다운·칩·가드 전부 엔진이 판단). 봇 전용 우회 금지.
- 말풍선(선택, 살짝만): 맞았을 때 '아야!' 계열, 합의금 낼 때 '합의금이다!' 계열, 때린 뒤 '😤'. `t.emote(token,'text',짧은글)` 이 거절(2.5초 쿨다운)돼도 오류 없이 넘어간다.
- 시험 `test-hit-bots.js`: 연습 테이블(`practice=true`, 빠른 모드, 봇 4~9명 + 사람 1명이 항상 call/check)을 수천 핸드 돌려서 ① 봇이 때리고 ② 봇이 합의금을 내고 ③ 봇이 기절하는 일이 실제로 생기며 ④ 쿨다운(H,H+1,H+2 불가)이 항상 지켜지고 ⑤ 칩 합계(`Σchips + 진행 중 pot`)가 보존되고 ⑥ 교착·예외가 없음을 확인.

## 5. 클라이언트 명세
- **새 모듈 `public/hit.js`**: `index.html` 이 `stage` 를 만든 뒤 `import('./hit.js').then(m => m.init(api)).catch(console.error)` 로 **동적 로드**(실패해도 게임은 그대로). `api = { send, toast, getState, getStage, fmt, esc }`. 매 상태 반영 때(`renderUI()` 끝) `m.update(S)` 호출.
- `punch.js` 도 `import('./punch.js').then(m => m.attachPunch(Stage))` 로 동적 로드(실패해도 안전).
- **옛 서버 호환**: `S.hit` 가 없으면(옛 서버) 때리기 UI 를 전부 숨기고 아무 오류도 내지 않는다.
- **버튼** `⚾ 때리기` (`#hitPill`): 상단바 💬(`#chatBtn`) 오른쪽. `S.hit && S.handNo>0 && !S.ended` 일 때만 보임. 지금 못 때리는 상태(스위치 꺼짐/쿨다운/연출 중/칩 부족/기절 등)면 흐리게 표시하되 **눌러도 사라지지 않고** 이유 문구를 토스트로 보여 준다(스위치 꺼짐이면 정확히 `방장 권한으로 폭력은 안됩니다.`). 가능하면 누르면 **대상 고르기 모드**(`body.hitmode`, 때릴 수 있는 사람 플레이트에 주황 점선 + 위쪽 안내 `⚾ 때릴 사람을 눌러주세요 · 1,000칩 [취소]`, Esc 도 취소) → 사람을 누르면 **확인창**(내 칩 변화, "맞은 사람은 다음 핸드를 기절해서 쉬어요 (1,500원을 내면 풀 수 있어요)", "때린 핸드부터 3핸드 동안은 아무도 못 때려요") → `send({t:'hit', i})`.
- **방장 스위치** `#hitSw`: `#hostBtns` 맨 앞. 방장에게만 보임(`#hostBtns` 가 이미 방장 전용). `⚾ 때리기 허용 ON/OFF`, 누르면 `send({t:'hitSwitch', on: !S.hit.on})`. 기본 ON.
- **맞은 사람 배너**(`.hudmid` 안, 내용이 바뀔 때만 innerHTML 갱신 — 매 프레임 갈아끼우면 버튼 클릭이 씹힌다): `me.stun==='pending'` → 제목 `😵 기절로 인한 다음 핸드는 플레이가 불가합니다`, 부제 `다음 핸드를 뛰려면 때린 ○○님에게 1,500원을 보내야 해요`, 버튼 `1,500원 보내고 뛰기`(칩이 모자라면 비활성 + `칩이 부족해요`) → `send({t:'payStun'})`. `me.stun==='out'` → `😵 기절 중 · 이번 핸드는 쉬어요 / 이 핸드가 끝나면 깨어나요`.
- **배지**: `players[i].stun` 이 있으면 그 사람 플레이트 요소(`stage.seats[i].el`)의 **별도 자식 span**(플레이트 `className`/`.plate.innerHTML` 은 상태마다 다시 그려져서 거기 붙이면 지워진다)으로 `💫 기절 예정 · 다음 핸드 쉼` / `😵 기절 중 · 이번 핸드 쉼`.
- **기절 모션**(`punch.js` 의 `stun/wake`): `game3d.js` 의 `hud(st)` 안에서 `players[i].stun==='out'` 이고 아바타가 아직 `stunned` 가 아니면 `this.stun(i)`, `stun` 이 `''` 인데 `avatar.stunned` 면 `this.wake(i)`. (`'hand'` 이벤트 처리에서 `hud({...st,toAct:-1})` 를 부르므로 핸드 시작 순간에 쓰러진다. 새로 접속/새로고침해서 이미 기절 중이어도 같은 경로로 맞춰진다.) 내가 기절하면 화면이 어두워지며 `😵 기절!` 가 잠깐(약 2.4초) — 나는 1인칭이라 `stun()` 이 몸을 보이게 바꿔 준다.
- **때리는 연출**: `game3d.js` 에 `pushEmotes` 와 같은 방식의 `pushHits(st)`(큐를 기다리지 않고 도착 즉시) 추가, `index.html` 의 `onMsg` 에서 `stage.pushEmotes(m)` 옆에서 호출. `hit` 이벤트 → `this.punch(ev.i, ev.to, 'b')`(`await` 하지 않음 = 판 진행과 병행), `pay` 이벤트 → 말풍선. 들어오기 전의 이벤트는 재생하지 않는다(`first` 처리, `hitSeen`). 탭이 숨겨져 있으면(`document.hidden`) 연출은 건너뛴다. `tw.fast` 면 `punch()` 가 즉시 끝나는 것이 정상.
- **떠오르는 칩 글자**: `hit`/`pay` **이벤트가 도착한 순간** `−1,000`(때린 사람, 붉은색) / `+1,000`(맞은 사람, 초록) 이 플레이트 위로 1.5초 떠올랐다 사라진다(Web Animations API, DOM 요소 1개씩). 숫자는 서버 상태대로 **즉시** 바뀐다(지연 금지).
- **정산**은 칩 기준이라 자동 반영. 정산 화면·연습 종료 흐름은 건드리지 않는다.
- **미리보기 정리**: `punch-flow.js` 는 삭제하고, `punch-demo.js` 는 모션 시연 도구(때리기 B/기절 보기/깨우기/속도/FPS)만 남기되 `punch-flow` 를 import 하지 않는다. `?punch` 는 개발용으로만.
- **렉 금지**: 프레임당 새 객체 금지, 새 조명/그림자 금지, DOM 은 이벤트/상태 변화 때만 갱신. `punch-demo` 의 FPS 측정으로 확인(60fps, 최대 끊김 ≤ 20ms 안팎).
- 폰(393×852, 세로)에서도 상단바·대상 고르기·배너·확인창이 깨지지 않을 것.

## 6. 서버 통합 시험 (`test-hit-server.js`, 포트 3102, `HOLDEM_FAST=1`)
`test-practice.js` 와 같은 방식(ws 로 접속)으로: ① 일반 테이블에서 사람 3명 → 한 명이 `hit` → 모두의 상태에 칩 변화·`stun`·`hit` 이벤트·`hit.lastHitHand` ② 같은 핸드에 다른 사람이 `hit` → 에러 문구, 에러는 보낸 사람에게만(상태 방송 없음) ③ 맞은 사람 `payStun` → 칩·이벤트·`stun` 해제 ④ 방장 `hitSwitch` off → 문구, 방장 아님 → 거절 ⑤ 다음 핸드에서 기절한 사람은 `cards` 가 비어 있고 `inHand=false` ⑥ 연습 테이블에서 사람이 맞고(봇이 때리는 건 `bot.js` 시험 몫이라 여기선 서버 메서드 직접 호출 허용) 사람이 `payStun` ⑦ 칩 합계 보존·정산 합계 0.
